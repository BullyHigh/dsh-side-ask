# 侧边提问 (Side ask)

[English](README.md) | 中文

主对话继续跑，你可以在右侧栏新开一个**只读**的「侧边提问」会话，就当前对话追问一句。提问会话从当前时刻完整复制对话（包括正在进行、还没结束的那一轮），模型能看到全部上下文，但标签页本身从空白开始——被复制过来的历史不显示；主输入框里还没发送的草稿会自动带过去。关闭标签会先停掉侧边会话可能还在跑的工作，再静默归档。

这是一个 DeepSeek Harness（DSH）组合包（`dsh.bundle`），适用于 0.2.2-rc.5 及以上的 0.2.x。没有依赖、没有构建步骤：包里就是成品 Host 半边和浏览器半边。

## 安装

- **桌面端**：打开 **插件** → **添加插件**（或右侧箭头 → **安装第三方插件**），粘贴 `github:BullyHigh/dsh-side-ask`。Desktop 的 profile 由应用独占管理，命令行装不进去。

- **命令行**：针对 web（或 npm 安装）的 profile，要指明 profile 名：

  ```sh
  dsh plugin --profile web add github:BullyHigh/dsh-side-ask
  ```

- **Tarball**：从 [Releases](https://github.com/BullyHigh/dsh-side-ask/releases) 下载 `dsh-side-ask-<version>.tgz`，在**添加插件**里选择该文件（命令行：`dsh plugin --profile <名字> add /绝对路径/dsh-side-ask-<version>.tgz`）。

- **源码目录**：在**添加插件**里选中本仓库的克隆目录。这会安装一个链接，所以目录不能挪走。

如果插件页提示需要重启，就重启 DSH。插件只用 DSH 的 Client 服务与插槽，外加一个内部斜杠命令；换到差异较大的 DSH 版本可能需要更新。

## 用法

- **头部按钮**：对话标题旁的对话气泡按钮。
- **快捷键**：桌面端 `Alt+Q`，浏览器 `Ctrl+Alt+Q`（macOS `Cmd+Alt+Q`）。可在**设置 → 快捷键**（`sideAsk.open`）里改。同一个对话再按一次会复用已有侧边提问，而不是再开一个。
- **划词菜单**：在对话正文里选中文字，浮动菜单会出现「引用文本」和「侧栏提问」。点「侧栏提问」会打开（或切到）侧边提问，并把选中的文字作为引用放进它的输入框。
- **右侧栏的「+」菜单**：指南页里有「侧栏提问」卡片，和内置工具并排。

划词菜单本身是宿主「引用」交互的按钮位，本插件只是在同一位置画了自己的表面：引用行为仍由宿主处理，卸载插件后宿主的「引用文本」按钮会自动恢复。
- 右侧栏标签就是普通对话界面（滚动、停止、权限控制），标签头上有一个**只读**徽标。它打开时记录是空的：只显示你在侧边会话里真正问过的轮次。
- 新建侧边提问时，主输入框里未发送的文字会移入侧边输入框（只搬文字，已暂存的附件留在主输入框）。
- 关闭标签会停止侧边会话中正在跑的工作并静默归档。可在会话列表里勾选**显示已归档**找回，取消归档后继续。

## 实现要点

1. 在对话当前持久末尾（最新事件 seq）上 fork（`ctx.sessions.fork`），所以侧边提问能看到点击那一刻之前的历史，包括正在执行的那一轮；只有完全没有持久事件的对话才退化为空白会话。
2. 子会话标题为 `Side ask · <原标题>`，Host 内部命令 `/side-ask-readonly <session-id>` 往它的会话日志追加 `sandbox/mode = read-only` 与 `approval/policy = ask`。
3. 通过 `ctx.conversation.input.for(scope)` 读取父会话草稿，用 `requestDraftInitialization` 写入子会话；只有标签真正打开、且父草稿仍是那段文字时才清空父草稿。
4. 标签正文渲染内置的 `conversation.content` 工厂；一条作用域规则隐藏 fork 继承来的所有轮次编号（记录在资源地址的 `?quiet=<n>` 上）和更早历史的边界，所以看起来是空的；在侧边会话里新建的轮次编号更大，正常显示。
5. 关闭标签用 `stopActivity: true` 归档子会话；归档失败会弹出带**重新打开**的错误提示，父子映射保留，下次还是同一个子会话而不是重新 fork。

内部命令会出现在本版本 DSH 的 `/` 命令列表里，但它的对话行是隐藏的；它只接受自己所在会话的 id，在普通对话里执行没有效果。

## 限制

- 空白记录是显示规则，不是上下文裁剪：被隐藏的轮次仍在侧边会话里，模型可以引用和转述。
- fork 复制的是持久事件；点击那一刻还在流式输出的助手文本，要等它落定后才会进入副本。
- 主输入框里已暂存的附件不会搬过去，只有文字草稿会。
- 两个会话共用一个工作目录。只读沙箱是唯一的写入屏障，而且只管文件操作——不管网络、进程和凭据。
- 模型仍可申请临时提升沙箱权限（`sandbox_permissions`）；`approval/policy = ask` 会强制走人工审批。
- 归档不是删除：日志、索引和 spill 文件仍在磁盘上；已归档会话可能仍出现在搜索里，并带有取消归档操作。
- 已归档会话不能直接打开，先取消归档。
- 归档会累积，DSH 没有批量删除。只能逐个取消归档，或自行删除存储文件（不受支持，有风险）。
- 工具集跟随源会话（fork 复用其预设），所以联网搜索、读文件、只读命令都能用，只有写入会被拒绝。
- fork 使用当前默认模型，可能与源会话使用的模型不同。
- 侧边会话带有源对话目标的副本，但自动续跑是关闭的，不会自己多跑几轮。
- 刷新页面或禁用插件不会归档侧边提问；子会话会留在列表里，直到你再次打开或在列表里归档它。
